## 目标

把产品基线拆分成具有进入、退出门槛的开发里程碑，在运行时代码启动前明确技术边界、验收归属、主要风险和待确认的需求缺口。

## 范围

- 分解 v0.1.0 的实施关键路径。
- 将 30 条验收条件映射到主责任里程碑。
- 明确前端、Tauri、SQLite、交互和测试边界。
- 审查需求是否足以支持从空白状态开始使用。

## 完成结果

- 形成 Proposed 状态的 M0–M7 实施计划。
- 建议使用 Rust 存储层封装 SQLite 事务，不让前端直接执行任意 SQL。
- 识别出母任务无法新建以及任务无法删除、重命名的基础数据维护缺口。
- 提出最小任务管理补充范围，等待用户与整体计划一并确认。

## 验证

- 对照现有 30 条验收条件检查里程碑归属。
- 核对 ADR-0001 与仓库结构约定。
- 核对 Tauri commands、SQL plugin migration 和 SQLite transaction 的官方资料。
- 本轮只制定计划，未初始化工程或运行代码测试。

## 遗留事项
