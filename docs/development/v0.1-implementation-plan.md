# v0.1 开发实施计划与里程碑

- 状态：Accepted
- 制定日期：2026-09-17
- 确认日期：2026-09-17
- 当前里程碑：M7 发布候选与正式验收
- 目标版本：v0.1.0
- 产品基线：[工作规划时间板需求文档](../requirements/planning-board-prd.md)
- 已接受决策：[ADR-0001](../decisions/ADR-0001-local-first-tauri-desktop.md)

## 1. 目标

交付一个 Windows 优先、可安装、断网可运行的本地工作规划时间板。v0.1.0 完成现有 30 条验收条件，并形成可继续演进的数据迁移、测试和发布基础。

本计划定义实施顺序与验收门槛。计划已于 2026-09-17 获得确认，实施从 M0 开始按顺序推进。

## 2. 范围边界

### 2.1 v0.1.0 包含

- 母任务与子任务的本地规划数据；
- 周、双周、月时间线及日期导航；
- 子任务新增、编辑、拖动与按天拉伸；
- 母任务间多重前置依赖、环检测和排期冲突提示；
- SQLite 自动保存；
- 版本化 JSON 的完整导入与导出；
- Windows 安装包、离线启动与数据升级验证。

### 2.2 v0.1.0 不包含

- 登录、云同步、多人协作和遥测；
- 进度、完成率、逾期、工时和人员负荷；
- 子任务级依赖、关键路径和自动排程；
- 自动备份与版本历史；
- macOS、Linux 的正式发布承诺；
- 真正的“数据随程序目录移动”的便携模式。

### 2.3 已确认的必要范围补充

现有需求能导入母任务，也能新增子任务，但没有定义母任务的新建、重命名、删除，也没有定义已有子任务的重命名和删除。若保持原文，空白安装后的用户无法建立第一项规划，也无法纠正误建数据。

以下最小能力已确认纳入 v0.1.0，并已回写需求基线：

1. 新建、重命名母任务；
2. 删除母任务，若包含子任务或依赖则二次确认，并同步删除相关依赖；
3. 重命名、删除子任务，删除需要二次确认；
4. 母任务和子任务继续保持创建顺序，v0.1.0 不增加手动排序功能；
5. 首次启动为空白画板，提供清晰的新建与导入入口，不自动写入演示数据。

该补充只解决基础数据可维护性，不引入任务状态或项目管理属性。

## 3. 拟采用的实现基线

会长期影响实现的存储边界已记录为 [ADR-0002](../decisions/ADR-0002-rust-sqlite-storage-boundary.md)。

| 层次 | 拟采用方案 | 约束 |
| --- | --- | --- |
| 桌面运行时 | Tauri 2 | Windows 首发，最小权限配置 |
| 前端 | React、TypeScript、Vite | npm 管理依赖，严格类型检查 |
| 样式 | 本地构建的 Tailwind CSS + CSS 设计变量 | 不使用 CDN；动态日期位置使用受控内联样式 |
| UI 状态 | React reducer/context 起步 | 未出现明确瓶颈前不引入全局状态框架 |
| 时间线 | HTML/CSS 定位任务条，SVG 绘制依赖线 | 不引入完整甘特图库，避免功能模型被第三方组件反向限制 |
| 拖动 | Pointer Events + pointer capture | 拖动中只预览，松手后写库一次 |
| 日期 | `YYYY-MM-DD` 日期值 + 集中的 date-only 工具 | UI 组件不得自行做毫秒和时区换算 |
| 本地存储 | Rust 存储层 + bundled SQLite | 前端不直接执行任意 SQL |
| 桌面调用 | 类型明确的 Tauri commands | 只暴露业务级命令，不暴露通用文件系统和 SQL 接口 |
| JSON 校验 | Rust 端权威校验，前端展示结构化结果 | 应用导入前重新校验，不能只相信预览结果 |
| 单元/组件测试 | Vitest + React Testing Library；Rust 单元测试 | 优先覆盖纯领域规则和数据事务 |
| 端到端测试 | Playwright 覆盖 Web 交互；桌面包执行发布清单 | 不用浏览器测试代替桌面离线验收 |

### 3.1 为什么不让前端直接使用 SQL 插件

官方 SQL 插件支持 SQLite 和 schema migration，但其 JavaScript API 当前没有完整的事务抽象；上游仍有事务支持的开放需求。覆盖导入和合并导入要求“全部成功或完全不写入”，因此本项目建议通过 Rust 存储层持有数据库连接，并使用 SQLite 原生事务完成批量变更。

Tauri commands 支持前端以明确参数调用 Rust 函数并接收结构化结果，适合作为本项目的窄接口边界。这样还可以在 Rust 层直接测试 migration、外键、回滚和导入事务。

### 3.2 初始数据模型

```text
app_meta
  schema_version

mother_tasks
  id, name, expanded, sort_order, created_at, updated_at

sub_tasks
  id, mother_task_id, name, start_date, end_date,
  sort_order, created_at, updated_at

dependencies
  task_id, depends_on_task_id

view_settings
  view_mode, anchor_date, show_dependencies
```

约束：

- `dependencies` 使用复合唯一键并启用外键；
- `end_date` 为空时业务上等于 `start_date`，保留“用户未填写结束日期”的语义；
- 母任务汇总起止日期不落库；
- 排期冲突是派生结果，不落库；
- 数据库 migration 一经发布只新增，不修改已发布 migration；
- JSON v1.0 以需求文档中的 `tasks/subTasks/dependsOn` 为权威格式，不兼容原型私有的 `motherTasks/children` 格式，除非后续单独决策。

## 4. 里程碑

实施遵循单一关键路径：

```text
M0 范围落档
  → M1 工程与桌面壳
  → M2 领域与数据内核
  → M3 可用时间板
  → M4 直接操作
  → M5 依赖关系
  → M6 数据交换
  → M7 发布候选
```

不跨过退出门槛提前宣称下一里程碑完成。

### M0：确认范围并落档（Completed）

目标：把本计划从 Proposed 转为 Accepted，消除实施前的范围歧义。

交付物：

- 将本计划状态改为 Accepted；
- 把 2.3 节确认后的最小任务管理能力写入需求基线和验收条件；
- 新增 ADR-0002，记录 Rust 存储层、SQLite 事务边界及放弃前端直连 SQL 的理由；
- 建立 v0.1.0 开发迭代记录。

退出门槛：产品范围、技术边界和第一阶段任务都能从仓库文档唯一定位。

相对工作量：3%。

### M1：工程基础与离线桌面壳（Completed）

目标：建立可重复开发、测试和打包的最小 Tauri 工程。

交付物：

- 初始化 React、TypeScript、Vite、Tauri 2 和 npm scripts；
- 建立 `src/`、`src-tauri/`、测试与静态资源目录；
- 建立 TypeScript、ESLint、Markdown、Rust format/clippy 和测试命令；
- 实现空白应用壳、错误边界和基础设计变量；
- 将字体和图标作为本地资源打包；
- 配置最小 Tauri capabilities，不开放 shell、任意路径或网络能力；
- 生成首个可启动的 Windows debug 包。

验证：

- 开发模式和桌面模式均可启动；
- 前端构建、类型检查、lint、单元测试、Rust 测试通过；
- 断网后应用壳能够启动，开发者工具中不存在外部资源请求；
- 仓库中没有提交构建产物。

退出门槛：后续开发可以在不调整基础构建路线的情况下进行。

相对工作量：10%。

### M2：领域规则与 SQLite 数据内核（Completed）

目标：先建立可信的数据与规则层，再让 UI 依赖它。

交付物：

- TypeScript 与 Rust 的母任务、子任务、依赖和视图设置类型；
- SQLite 初始 migration、外键、索引和数据库初始化；
- 业务级 Tauri commands 与前端 storage gateway；
- 母任务、子任务最小 CRUD 和顺序保持；
- date-only 工具、单日任务归一化、母任务排期汇总；
- 有向图环检测、自我依赖校验和排期冲突判断；
- 内存 adapter，供组件测试和浏览器开发预览使用；
- 写入失败时的结构化错误与 UI 回滚约定。

验证：

- Rust 测试覆盖 migration、CRUD、级联规则和事务回滚；
- TypeScript 测试覆盖日期边界、汇总、环检测和冲突判断；
- 修改数据后退出并重启桌面应用，数据不丢失；
- 数据库初始化失败时显示可理解错误，不进入假成功状态。

主要对应验收条件：5、8、13、15、22。

退出门槛：UI 无需知道 SQL、数据库路径或文件系统路径即可完成全部数据操作。

相对工作量：17%。

### M3：可用的时间板垂直切片（Completed）

目标：在不依赖拖动和依赖连线的情况下，形成可日常录入的时间板。

交付物：

- 周、双周、月视图及前后导航、回到今天；
- 真实日期表头、周末弱化和今天标记；
- 左侧层级列表与右侧时间线共享同一行模型；
- 母任务展开、收起、全部展开和全部收起；
- 母任务汇总条、子任务条和跨视图区间裁切；
- 母任务与子任务的最小管理界面；
- 通过 `+ 子任务` 新增以及点击任务条编辑名称和日期；
- 搜索母任务和子任务；
- 空白首次启动与空状态引导；
- 所有表单校验、自动保存和失败反馈。

验证：

- 组件测试覆盖三种视图、日期导航、过滤、展开状态和表单校验；
- 端到端测试覆盖“新建母任务 → 添加子任务 → 修改日期 → 重启仍存在”；
- 在不同窗口宽度和横纵滚动位置检查左右行对齐；
- 任务超出视图时只裁切展示，不修改真实日期。

主要对应验收条件：1–6、8、9、19–21。

退出门槛：即使尚未实现拖动，用户也能从空白应用建立并维护一份规划。

相对工作量：24%。

### M4：时间板直接操作（Completed）

目标：完成产品最核心的画板式规划体验。

交付物：

- 双击母任务时间区域按目标日期快速添加子任务；
- 拖动任务条整体移动，保持持续天数；
- 左右边缘拉伸工期，按完整日期吸附；
- pointer capture、点击/拖动阈值和越界处理；
- 拖动中的日期预览、Hover 提示和保存后 Toast；
- 松手时一次性持久化，失败则回滚到原排期；
- 鼠标操作之外保留日期编辑表单作为键盘和无障碍替代路径。

验证：

- 单元测试覆盖像素位移到日期偏移的换算和最小一天规则；
- 端到端测试覆盖点击、双击、拖动、左右拉伸与阈值区分；
- 快速连续操作不会产生重复任务或中间日期写库；
- 拖动完成后刷新或重启，排期与画面一致。

主要对应验收条件：7、10–13、19。

退出门槛：六项核心交互中的日期快速新增、整体拖动、两端拉伸和视图切换已形成完整闭环。

相对工作量：15%。

### M5：母任务依赖与冲突提示（Completed）

目标：表达多重前置关系，并在排期改变后可靠重算。

交付物：

- 可搜索、多选的前置母任务设置；
- 单独解除依赖；
- 自我依赖、重复依赖和循环依赖拦截；
- SVG 依赖连线、箭头、总开关和 Hover 聚焦；
- 普通与冲突连线样式、母任务警示标记；
- CRUD、拖动、编辑和导入后统一重算依赖状态；
- 删除母任务时清理相关正反向依赖。

验证：

- 图算法测试覆盖链、分叉、多父节点和多种环；
- 冲突边界覆盖“后置开始日等于前置结束日”；
- 端到端测试覆盖新增、解除、隐藏、聚焦和拖动后重算；
- 冲突只提示，不自动改动任何任务日期。

主要对应验收条件：14–18。

退出门槛：依赖数据、连线和冲突提示在所有会改变排期的入口下保持一致。

相对工作量：14%。

### M6：JSON 导入、导出与数据安全（Completed）

目标：完成本地资产的备份、迁移与恢复闭环。

交付物：

- 固定 JSON v1.0 schema、序列化顺序和版本兼容策略；
- 全量导出、默认文件名和系统保存对话框；
- 系统打开对话框与拖拽文件导入；
- 导入预览、覆盖/合并选择和覆盖二次确认；
- 文件类型、结构、唯一 id、日期、引用、自依赖和环完整校验；
- 缺省 `endDate` 与旧版缺省字段补齐；
- 合并模式的 id 匹配与无 id 回退规则；
- Rust 单事务导入，任何错误均回滚；
- 导入后定位最早日期、重算排期和冲突；
- 可操作的错误清单与成功统计。

验证：

- 使用有效、格式错误、字段缺失、非法日期、悬空引用和循环依赖夹具；
- 导出后覆盖导入，数据语义一致；
- 导入失败前后数据库快照一致；
- 搜索、视图和依赖显示开关不影响导出的全量内容；
- 整个流程在断网环境中完成。

主要对应验收条件：23–30。

退出门槛：用户可以可信地备份、恢复和迁移全部规划数据。

## 6. 每个里程碑的统一完成定义

一个里程碑只有同时满足以下条件才能标记 Completed：

1. 范围内功能具有可操作的纵向闭环，而非只有静态页面；
2. 新增规则有相应单元、组件或端到端验证；
3. TypeScript 类型检查、前端 lint/test、Rust fmt/clippy/test 和构建通过；
4. 失败场景有明确反馈，不静默丢数据；
5. 相关需求、ADR、迭代记录和变更日志同步更新；
6. 未执行的检查明确写为未执行，不以局部测试代表完整验证；
7. Git 变更范围清晰，不夹带生成物、用户数据库或无关文件。

## 7. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 日期受时区或夏令时影响偏移 | 使用 date-only 值和集中换算；不在组件中直接解析日期字符串为本地时间 |
| 左右列表滚动或行高失配 | 两侧使用同一行模型与统一高度变量；建立滚动对齐测试 |
| 拖动高频写库导致卡顿或脏数据 | pointer move 仅更新预览，pointer up 才提交一次 |
| 导入过程中部分写入 | Rust 层重新校验并在单个 SQLite 事务中执行 |
| 多重依赖形成环 | 保存前图算法校验，数据库写入入口统一执行 |
| 原型反向扩大产品范围 | 原型只取视觉参考，功能以需求和 Accepted ADR 为准 |
| Tauri 权限过宽 | 使用业务级 commands 和最小 capabilities，不暴露通用 shell/SQL |
| 浏览器测试通过但桌面包失败 | 每个关键阶段做桌面冒烟，M7 必须在打包产物上断网验收 |
| 首发范围被进度/协同需求稀释 | 新能力先进入需求和决策流程，不直接插入当前里程碑 |

## 8. 确认记录

本计划于 2026-09-17 获得确认，确认内容包括：

1. 接受 M1–M7 的实施顺序与里程碑退出门槛；
2. 接受 2.3 节的最小母任务/子任务管理补充；
3. 接受“Rust 存储层 + bundled SQLite + 业务级 Tauri commands”的拟定边界；
4. v0.1.0 首发只承诺 Windows 安装版，不承诺真正便携模式；
5. 每完成一个里程碑先提交验证与文档结果，再进入下一里程碑。

M0 已完成，项目进入 M1。后续仍需遵守各里程碑退出门槛，不以计划获批替代阶段验证。
