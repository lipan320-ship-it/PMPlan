# 项目规划文件与最近打开设计

- 日期：2026-09-29
- 状态：设计已确认，待编写实施计划
- 范围：桌面端项目文件、最近打开、自动回写、视图设置隔离和旧数据迁移

## 1. 目标

用户可以选择最近打开的项目规划；应用启动时默认打开上一次成功打开的项目规划；打开不同 JSON 后，任务修改只写回当前项目对应的 JSON 文件，不再因为切换文件而只能覆盖或合并同一个 SQLite 画板。

本设计选择“当前 JSON 项目 + SQLite 工作缓存”方案：JSON 是用户可见的项目持久文件，SQLite 继续负责当前项目的事务、校验和应用恢复。每次修改完成后自动将当前规划快照原子写回活动 JSON；SQLite 和 JSON 之间没有跨存储的单一事务，因此保存失败必须显式进入未保存状态并提供恢复动作。

本需求不新增版本历史或操作日志。这里的“修改记录保存”指当前规划数据被写回对应 JSON 文件；历史版本仍由用户的文件备份或版本控制工具管理。

## 2. 当前问题

当前实现只有一个应用级 SQLite 数据库：`src-tauri/src/lib.rs` 在启动时固定打开应用数据目录下的 `pmplan.sqlite3`。`StorageGateway` 没有项目身份、源文件路径或最近项目接口。

当前“导入 JSON”流程选择文件后只构造临时 `ImportSource`，再以覆盖或合并模式写入同一个 SQLite 数据库；导入源路径不会绑定到当前画板。之后的任务编辑只写 SQLite，原 JSON 文件不会更新。导出则每次通过保存对话框另选目标路径。

现有 ADR-0001 和 ADR-0002 将 SQLite 定义为权威存储，并明确拒绝直接保存单个 JSON。新需求改变了项目文件边界，必须通过新的项目持久化决策替代这部分约束，同时保留 JSON 导入/导出和 SQLite 事务能力。

## 3. 已确认的产品决策

| 决策项 | 规则 |
| --- | --- |
| 保存语义 | 打开项目后，任务、依赖、排序、展开状态等规划修改自动回写同一路径 JSON |
| JSON 范围 | JSON 只保存规划数据；视图设置按项目路径保存到应用本地元数据 |
| 新建项目 | 新建时立即打开另存为对话框，先创建合法空 JSON，再设为当前项目 |
| 最近项目 | 保留最近 8 个规范化绝对路径；成功打开、新建或另存为后置顶 |
| 失效项目 | 文件不存在、不可读或 JSON 无效时保留条目并标记原因，可移除记录；移除不删除源文件 |
| 启动恢复 | 优先打开上一次成功打开的项目；失败时保留失效条目并进入项目选择入口 |
| 外部修改 | 记录修改时间和内容哈希；发现外部变化时暂停自动回写并让用户选择处理方式 |
| 旧数据 | 首次升级提示另存为 JSON；完成前保留未命名 SQLite 工作区和原数据 |
| 导入/导出术语 | “打开项目”是切换项目；“导入 JSON”仍是对当前项目的覆盖/合并；“导出 JSON”仍是另存副本 |
| 季度总览 | 继续是临时浏览状态，不写入 `ViewMode`，不改变现有周/双周/月枚举和 SQLite 约束 |

## 4. 用户流程

### 4.1 启动

1. 读取应用元数据中的活动路径和最近项目列表。
2. 如果活动路径对应的 JSON 存在且完整校验通过，加载它作为当前项目，恢复该路径的视图设置，并把它置顶。
3. 如果文件不存在、不可读或校验失败，保留最近项目条目，显示失效原因和项目选择器；不创建空项目覆盖原路径。
4. 如果没有活动路径且旧 SQLite 有任务数据，显示一次旧数据迁移提示；用户可以另存为 JSON，也可以暂时继续未命名工作区。
5. 如果没有项目和旧数据，显示现有空白画板入口。

### 4.2 打开项目

打开项目先读取完整文件并执行现有 v1.x 校验，包括 JSON 结构、日期、重复 id、依赖引用、自依赖和循环依赖检查。校验通过后，才在一次 SQLite 事务中替换当前缓存并写入活动路径、文件指纹和最近项目元数据。

打开失败时，当前项目、当前缓存和视图设置均保持不变。成功打开 A 后再打开 B，B 的任务、依赖和视图设置替换当前上下文；A 的文件不会被覆盖或合并。

### 4.3 修改与自动保存

每个会改变规划数据的命令都经过统一的变更持久化包装：

1. 在 SQLite 事务中完成现有校验和数据变更。
2. 从当前缓存生成完整 JSON v1.x 快照。
3. 检查活动文件的修改时间和内容哈希是否仍与上次成功读写的基线一致。
4. 在目标文件同一目录写入临时文件，并原子替换原文件。
5. 成功后更新文件指纹、保存状态和最近项目元数据。

保存队列按项目令牌串行执行。切换项目或关闭应用时，旧项目的延迟保存不得写入新项目。

如果 SQLite 事务已提交但 JSON 写入失败，规划修改保留在缓存中，界面显示“未保存”或具体失败原因，不显示保存成功。用户可以重试、另存为新文件或继续编辑；后续成功保存必须覆盖当前未保存快照。

### 4.4 外部修改冲突

自动保存前同时比较文件修改时间和内容哈希：

- 指纹未变化：继续原子写入。
- 文件已被外部修改：暂停写入，显示“文件已在外部修改”。用户可以重新加载外部文件、另存为新文件或取消。
- 文件已删除或权限不可用：进入未保存状态，允许重新选择路径或重试。

重新加载会丢弃当前未保存缓存，必须经过确认；另存为会把当前缓存写入新路径并把新路径设为活动项目；取消保持当前缓存和原活动路径，不静默覆盖外部文件。

### 4.5 导入、导出和新建

- **导入 JSON**：保留现有预览、覆盖确认和合并语义。导入作用于当前缓存，成功后按照当前活动项目的自动保存规则写回当前 JSON；未命名工作区则继续使用 SQLite，直到用户另存为项目文件。
- **导出 JSON**：保留为另存副本，不改变活动项目路径、最近项目顺序或视图设置。
- **新建项目**：创建合法空 JSON，成功后切换到该路径；如果路径已有文件，遵循保存对话框的覆盖保护。

## 5. 架构和数据边界

### 5.1 项目会话层

在现有 Rust `Storage` 与 Tauri commands 之间增加项目会话职责，统一管理：

- 活动项目路径和项目令牌；
- 当前缓存的加载、替换和未命名工作区状态；
- 最近项目索引；
- 按路径的视图设置；
- 文件指纹和保存状态；
- 原子 JSON 读写和冲突检查。

React 只通过 `StorageGateway` 调用项目业务命令，不直接拼接文件路径或维护持久化副本。

### 5.2 建议的应用元数据

SQLite schema migration 增加以下逻辑结构；具体表名可以沿用仓库命名规范，但约束必须保持：

#### 活动项目

- `active_project_path`：规范化绝对路径，可为空；
- `workspace_mode`：`named_project` 或 `unnamed_legacy`；
- `save_status`：`saved`、`saving`、`unsaved`、`conflict` 或 `error`。

#### 最近项目

- `path`：主键，按 Windows 大小写不敏感规则去重；
- `last_opened_at`：最近成功打开时间；
- `status`：`available`、`missing`、`unreadable`、`invalid`、`conflict`；
- `last_error`：可展示的原因，可为空；
- `last_modified_at` 和 `last_content_hash`：最近成功读写的指纹。

列表最多保留 8 条。超过上限时移除最旧条目，不触碰源文件。

#### 项目视图设置

按规范化项目路径保存 `viewMode`、`anchorDate`、`showDependencies`、`taskColumnWidth` 和 `motherSortMode`。视图设置缺失时使用现有默认值。季度总览不写入该枚举，只由前端继续保存为临时状态。

现有 singleton `view_settings` 可继续作为运行时当前视图和未命名工作区的兼容存储；打开命名项目时从路径记录加载，视图变更同时更新当前运行时设置和路径记录。迁移不能扩大 `ViewMode` 的取值范围。

### 5.3 业务命令边界

项目层需要提供与 `StorageGateway` 对应的能力：

- `listRecentProjects`；
- `openProject(path)`；
- `createProject(path)`；
- `saveActiveProject()`；
- `saveAsProject(path)`；
- `reloadExternalProject()`；
- `removeRecentProject(path)`；
- `getProjectState()`。

现有任务 CRUD、依赖、排序、视图设置、导入和导出命令继续保留，但所有会改变规划数据的命令必须经过统一自动保存包装。命令返回的错误代码和保存状态必须能区分校验失败、文件冲突、文件不可用和数据库错误，不能把 SQLite 成功提交误报成 JSON 已保存。

## 6. 兼容性和迁移

### JSON 兼容

规划文件继续使用当前 `version: "1.x"` 结构，任务、子任务、依赖、标签和展开状态字段保持兼容。视图设置不加入 JSON，避免破坏现有交换文件和外部工具。

### 旧 SQLite

升级后的首次启动检查活动项目路径和现有任务：

- 有活动路径：按路径加载 JSON；SQLite 中的旧缓存只作为恢复依据，不覆盖文件。
- 无活动路径且 SQLite 有数据：进入旧数据迁移提示；用户另存为成功后写入活动路径和 MRU，并保留原数据库数据。
- 用户暂不迁移：继续未命名 SQLite 工作区，允许稍后另存为；不把它伪装成已有 JSON 项目。
- 无任务数据：直接进入空白入口。

迁移失败时不删除、不清空旧 SQLite 数据，也不写入不完整 JSON。

### 现有导入行为

覆盖和合并导入的全量校验、单事务应用、失败不污染当前数据规则保持不变。导入与打开项目必须在 UI 文案、gateway 接口和测试中明确区分。

## 7. 验收与测试

### 项目和 MRU

1. 首次启动无项目时显示空白入口。
2. 打开 A 后重启默认打开 A；打开 B 后重启默认打开 B。
3. 最近列表最多 8 条，规范化路径去重，显示文件名和父目录。
4. 失效条目保留原因，可移除；移除不会删除源文件。
5. 路径大小写、相对路径和绝对路径的等价形式不会产生重复项目。

### 隔离和自动保存

1. 打开 A、修改并等待保存后，A JSON 包含修改。
2. 打开 B、修改并等待保存后，B JSON 包含修改，A JSON 语义内容不变。
3. 任务、子任务、依赖、排序、展开状态和视图设置分别按项目恢复。
4. 视图设置不进入 JSON，季度总览不改变 `ViewMode`。
5. 导入覆盖/合并仍只作用于当前项目；导出另存不会改变活动项目。

### 失败和冲突

1. 无效 JSON、缺失文件、只读文件和目标目录不可写时，不切换项目、不显示保存成功。
2. 自动保存失败后修改保留在缓存，界面显示未保存并支持重试/另存为。
3. 外部修改被检测到时不静默覆盖，重新加载、另存为和取消动作结果正确。
4. 快速连续修改、切换项目和关闭应用不会让旧项目的延迟写入污染新项目。
5. 旧 SQLite 数据迁移前后均可恢复，迁移失败不清空原数据。

### 验证层级

- Rust 单元/集成测试：路径规范化、MRU、原子写入、指纹冲突、A/B 切换、视图设置和旧数据迁移；
- TypeScript gateway 测试：项目命令、错误状态和导入/打开边界；
- React 流程测试：启动恢复、最近列表、保存状态、冲突处理和术语文案；
- 常规门禁：`npm.cmd` 测试、lint、build、Rust tests、`git diff --check`；
- 桌面视口和文件系统权限验证若环境不可用，必须在验收矩阵中标记为 Pending，不把设计验证写成已完成实现。

## 9. 明确不包含

- 云同步、账号、多用户协作和远程冲突合并；
- JSON 历史版本、操作日志或回滚时间线；
- 将季度总览加入持久化 `ViewMode`；
- 用隐藏的每项目 SQLite 副本替代用户可见的源 JSON；
- 把导入覆盖/合并改成默认的项目切换行为。
