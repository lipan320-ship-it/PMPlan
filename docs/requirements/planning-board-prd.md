## 1. 文档目的与产品定位

### 1.1 文档目的

本文档用于描述"工作规划时间板"的**功能范围、页面结构、交互方式、状态反馈及规则约束**，作为产品、UI、前端开发、测试实现页面时的统一依据。

### 1.2 产品定位

本页面不是一个传统甘特图，也不是项目进度管理系统，而是：

> **工作规划时间板（Planning Board / 可直接编辑的 Roadmap）**

核心目的是：**快速把母任务拆成子任务，并通过真实日期时间线安排"什么时候做、做多久"，同时表达母任务之间的需求依赖关系，并支持规划数据在本地以 JSON 形式导入导出。**

### 1.2.1 产品载体

首个正式版本采用 **Windows 优先的本地桌面应用**。本文中的“页面”指桌面应用内的主界面；文件选择、导入和导出使用系统文件对话框，运行时不依赖服务端或网络连接。技术选择及其边界见 [ADR-0001](../decisions/ADR-0001-local-first-tauri-desktop.md)。

### 1.3 核心命题

这个页面当前回答的是：

> **"未来这一段时间，我计划做什么？"**

而不是：

> **"这些任务现在执行得怎么样？"**

### 1.4 典型使用流程

```text
查看所有母任务
→ 展开某个母任务
→ 查看已有子任务
→ 新增子任务 / 双击日期快速新增
→ 给子任务设置日期
→ 在时间板上拖动调整时间
→ 设置母任务间的依赖关系
→ 根据依赖关系重新调整整体规划
→ 导出 JSON 备份 / 导入 JSON 恢复或迁移
```

用户应尽可能在当前时间板内完成规划，不需要频繁跳转其他页面。

## 2. 功能范围总表

下表为当前版本完整功能清单，已合并时间板规划能力、需求依赖能力与新增的 JSON 导入导出能力。

### 2.1 视图与定位

| 模块 | 功能点 | 交互 / 规则 | 用户故事 |
| - | - | - | - |
| 视图定位 | 工作规划时间板 | 左侧为母任务 / 子任务层级，右侧为日期时间线。不强调完成率、逾期、进度等项目管理属性 | 作为规划者，我希望一眼看到未来一段时间要安排哪些工作，而不是查看项目执行进度 |
| 页面结构 | 三层结构 | 第一层顶部时间控制；第二层母任务行；第三层子任务时间安排 | 我希望页面结构清晰，不用学习就能理解每块区域的作用 |

### 2.2 母任务与子任务

| 模块 | 功能点 | 交互 / 规则 | 用户故事 |
| - | - | - | - |
| 母任务列表 | 展示与排序所有母任务 | 母任务固定展示在左侧，每个母任务占一行；可展开 / 收起子任务，也可按住行首六点手柄拖动母任务上下调整顺序并自动保存 | 我希望先从较高层级浏览所有计划事项，并按自己的优先顺序组织它们 |
| 母任务管理 | 新建母任务 | 空白状态和工具栏提供新建入口；名称必填，新任务追加到列表末尾 | 我希望从空白画板开始建立自己的规划 |
| 母任务管理 | 重命名母任务 | 在母任务操作菜单中修改名称，保存后立即更新并持久化 | 我希望计划名称变化后可以直接修正 |
| 母任务管理 | 删除母任务 | 删除前二次确认；删除后同时移除其子任务以及指向或来自该任务的依赖关系 | 我希望清理不再需要的规划且不留下无效依赖 |
| 母任务行内容 | 行内元素 | 包含：展开 / 收起、母任务名称、子任务数量、依赖数量、依赖冲突提示，以及修改、依赖、添加子任务、删除四个图标操作按钮；图标保留可访问名称与悬浮提示 | 我希望在一个行内完成母任务相关的主要操作，同时保持界面紧凑 |
| 母任务展开 | 展开子任务 | 点击母任务名称或左侧展开箭头，展示 / 隐藏该母任务下所有子任务 | 我希望查看某个母任务具体被拆成了哪些工作 |
| 母任务收起 | 汇总排期 | 收起后隐藏子任务，但右侧仍展示该母任务下所有子任务覆盖的整体日期范围（最早开始 ~ 最晚结束） | 我希望收起细节后仍能快速判断各母任务大致安排在哪个时间段 |
| 母任务排期 | 自动汇总 | 母任务不单独设置时间，由子任务自动计算：开始 = 最早子任务开始日；结束 = 最晚子任务结束日；画板上用较细较弱的时间条表示 | 我希望母任务的时间自动跟随子任务，不需要二次维护 |
| 子任务展示 | 时间条 | 子任务以横向任务条展示，起点对应开始日期，终点对应结束日期，宽度代表持续时间 | 我希望直观看到某项工作计划在哪几天进行 |
| 子任务名称 | 条内展示 | 空间足够时显示名称；空间不足可截断，悬浮显示完整名称 | 我希望即使任务很多，也能快速判断每条计划是什么 |
| 子任务管理 | 重命名子任务 | 编辑子任务时允许修改名称；名称必填 | 我希望可以纠正规划事项的名称 |
| 子任务管理 | 删除子任务 | 编辑入口提供删除操作并二次确认；删除后重新计算母任务排期与依赖冲突 | 我希望可以删除误建或不再需要的子任务 |
| 添加子任务 | 从母任务直接添加 | 每个母任务行提供 `+ 子任务` 操作，不需要离开时间板 | 我希望做工作规划时直接拆任务，而不是进入另一个页面维护 |
| 快速添加 | 点击 / 双击日期创建 | 在某母任务时间线上点击或双击某一天（推荐双击，避免与拖动冲突），直接创建子任务，并默认该日期为开始日期 | 我希望看到某天有空档时直接把工作安排进去 |
| 新增子任务 | 最小输入 | 至少输入"子任务名称"；如果从某一天发起新增，则自动带入该日期 | 我希望尽量少填字段就能完成规划 |
| 默认工期 | 起始日即一天 | 只设置开始日期、不设置结束日期时，`结束日期 = 开始日期`，即默认为 1 天 | 我希望安排一天完成的事项时不用额外填写结束日期 |
| 日期设置 | 开始日期 | 子任务必须有开始日期 | 我希望每项工作至少明确什么时候开始 |
| 日期设置 | 结束日期 | 可选；为空则按一天处理；不能早于开始日期 | 我希望既能安排一天任务，也能安排连续多天任务 |
| 清空结束日期 | 恢复单日 | 编辑时清空结束日期，视为单日任务，而不是"未排期" | 我希望单日和多日计划之间切换简单 |
| 空状态 | 无子任务 | 母任务下没有子任务时，时间线区域直接显示 `+ 添加子任务` | 我希望没有拆解的工作能明显提示我继续规划 |
| 首次使用 | 空白画板 | 首次启动不自动写入演示数据，提供“新建母任务”和“导入 JSON”入口 | 我希望第一次打开时明确知道如何开始且不会混入虚构计划 |
| 子任务排序 | 保持原顺序 | MVP 保持用户原列表顺序，不按开始日期自动重排，避免拖动后列表跳动 | 我希望调整时间时界面不要突然改变位置 |
| 子任务排序 | 拖动调整顺序 | 展开母任务后，每个子任务行首显示拖动手柄，按住可在**同一母任务内**上下拖动调整顺序并自动保存；拖到其它母任务区域不处理，不支持跨母任务移动 | 我希望按自己的执行顺序组织同一母任务下的子任务 |

### 2.3 时间轴与导航

| 模块 | 功能点 | 交互 / 规则 | 用户故事 |
| - | - | - | - |
| 时间轴 | 使用真实日期 | 横轴显示具体日期，例如 `9/21 周一`、`9/22 周二`，不使用 W1 / W2 周编号作为主刻度 | 我希望排计划时直接对应实际日期，不需要再换算第几周 |
| 时间轴 | 周视图 | 展示连续 7 天；每天一个日期刻度 | 我希望规划近期一周的工作 |
| 时间轴 | 双周视图 | 展示连续 14 天；每天保留具体日期（**默认推荐**） | 我希望同时安排本周和下周工作 |
| 时间轴 | 月视图 | 展示当前自然月；仍以具体日期为基础，日期单元适当压缩 | 我希望从更长周期观察一个月内各工作的分布 |
| 视图切换 | 周 / 双周 / 月 | 顶部提供切换器。仅改变可见时间跨度与横向缩放，不修改任务数据、起止日期、依赖关系 | 我希望根据当前规划粒度快速切换观察范围 |
| 日期定位 | 今天 | 突出"今天"，使用细竖线 + 日期格浅色高亮 | 我希望快速知道当前时间在规划中的位置 |
| 日期导航 | 上一周期 / 下一周期 | 周模式前后移动 7 天；双周移动 14 天；月模式移动一个自然月 | 我希望快速查看过去或未来的规划 |
| 日期导航 | 回到今天 | 一键恢复到包含今天的时间段 | 我浏览未来计划后，希望快速回到当前周期 |
| 非工作日 | 周末弱化 | 周六、周日使用浅底色；不影响排任务，仍可新建 / 拖入 / 作为起止日期 | 我希望更容易区分工作日与周末 |
| 横向滚动 | 超出窗口滚动 | 时间跨度大于页面宽度时，时间区域允许横向滚动；左侧母任务区保持固定 | 我希望长时间范围下仍能对应任务与日期 |
| 纵向滚动 | 大量任务 | 时间线与左侧任务列表同步纵向滚动，保持统一行高 | 我希望几十个母任务情况下仍能使用 |

### 2.4 画板编辑交互

| 模块 | 功能点 | 交互 / 规则 | 用户故事 |
| - | - | - | - |
| 点击子任务 | 打开设置浮层 | 点击时间条弹出轻量 Popover，而不是大型详情页 | 我希望在当前规划上下文里快速修改任务日期 |
| 设置浮层 | 当前仅编辑时间 | 当前版本只开放"开始日期、结束日期"；不引入负责人、状态、优先级 | 我希望当前工具保持简单，只解决什么时候做的问题 |
| 设置浮层 | 即时保存 | 修改日期后立即更新画板并保存 | 我希望调整日期后马上看到新的排期 |
| 拖动任务 | 整体拖动 | 按住任务条主体左右拖动，整体移动开始 / 结束日期，并保持原有持续天数 | 我希望计划变化时直接把任务拖到新的日期 |
| 拖动吸附 | 按天吸附 | 吸附到完整日期单位，不产生 `9/23 14:00` 这类结果；时间精度固定为"天" | 我希望移动后的计划日期始终准确 |
| 拖动反馈 | 实时日期提示 | 拖动时显示例如 `9/23 → 9/25`；松手后 Toast 提示"已调整至 9/23–9/25" | 我希望移动任务时明确知道松手后会落在哪一天 |
| 调整工期 | 左右边缘拖动 | 悬浮任务条两端出现 Resize 光标；左端调整开始日，右端调整结束日 | 我希望直接在画板上把"2 天工作"改成"4 天工作" |
| 修改确认 | 松手生效 | 拖动或调整结束后直接保存，不需要确认弹窗 | 我希望规划操作流畅，不需要频繁确认弹窗 |
| 防误操作 | 点击与拖动区分 | 小幅点击打开设置；移动超过阈值（明显横向位移）才判断为拖动 | 我希望点击设置时不会误把任务移动 |
| 操作反馈 | Hover 状态 | Hover 时间条时增强高亮、显示可拖拽光标；Tooltip 显示名称 / 日期 / 操作提示 | 我希望明确知道任务条可以直接操作 |
| 边界处理 | 跨出当前视图 | 任务可跨越当前可视日期范围，只显示可见部分；切换周期后可查看完整范围，真实数据不变 | 我希望长任务不会因为当前只看一周而被限制 |
| 同日任务 | 允许重叠 | 同一母任务下多个子任务允许安排相同日期，不强制解决冲突 | 我希望先完成工作规划，而不是被系统强制做资源排期 |
| 跨任务安排 | 不限制重叠 | 不判断负责人冲突、工作量冲突等 | 我希望工具先服务规划，而不是变成复杂的资源管理系统 |
| 搜索 | 搜索母 / 子任务 | 根据名称过滤任务，时间线同步过滤 | 我希望快速定位某项计划 |
| 展开控制 | 全部展开 / 收起 | 保留"展开全部 / 收起全部" | 我希望在宏观规划和细节规划之间快速切换 |

### 2.5 需求依赖（来自 2.md）

| 模块 | 功能点 | 交互 / 规则 | 用户故事 |
| - | - | - | - |
| 需求依赖 | 设置母任务依赖 | 支持在母任务之间建立依赖关系，例如「B 依赖 A」 | 作为规划者，我希望标记某项需求必须在另一项需求之后开展，从而更合理地安排工作顺序 |
| 依赖类型 | 前置依赖 | MVP 只需要一种关系：**母任务 B 依赖母任务 A**，即 A 是 B 的前置需求 | 我希望明确知道某项工作开展前需要先完成哪些需求 |
| 多重依赖 | 一个任务可依赖多个任务 | 例如「VIP 系统」可同时依赖「埋点接入」和「任务系统」 | 我希望表达真实工作中一个需求存在多个前置条件的情况 |
| 被依赖关系 | 一个任务可被多个任务依赖 | 系统自动维护正反向关系，不需要用户分别配置 | 我希望一次配置后，双方都能看到关系 |
| 依赖设置入口 | 母任务操作菜单 | 母任务行提供「依赖 / 设置需求依赖」入口 | 我希望不离开当前时间板即可配置任务关系 |
| 依赖设置 | 选择前置母任务 | 弹窗中搜索 / 勾选其他母任务作为当前任务的前置依赖 | 我希望从现有母任务中快速选择依赖项 |
| 依赖展示 | 母任务行展示依赖标识 | 显示 `依赖 2`，Hover 或点击后查看具体依赖对象；无依赖时不显示 `依赖 0` | 我希望不用打开设置就能识别哪些任务存在依赖 |
| 画板展示 | 时间线上显示依赖连线 | 在母任务整体排期条之间绘制细线 + 箭头，例如 `A → B` | 我希望从时间线上直观看懂任务先后关系 |
| 展示控制 | 显示 / 隐藏依赖线 | 顶部提供「显示依赖关系」开关；关闭后隐藏连线但保留数据与 `依赖 N` 标记 | 我希望需要分析关系时打开，不需要时保持时间板简洁 |
| 依赖关系高亮 | Hover 聚焦 | Hover 某母任务时，重点高亮：当前母任务、它依赖的母任务、依赖它的母任务、对应连线；其他无依赖任务维持正常显示，不置灰 | 我希望看清依赖关系的同时仍能正常浏览其他任务 |
| 删除依赖 | 单独解除关系 | 在依赖设置弹窗中删除某一前置关系，不影响母任务本身 | 我希望修改计划关系而不影响任务数据 |
| 循环依赖校验 | 禁止循环依赖 | 若已有 `A → B → C`，则禁止设置 `C → A`，阻止保存并提示 | 我希望系统避免产生逻辑上无法成立的需求关系 |
| 自我依赖校验 | 禁止依赖自身 | 候选列表中不显示当前母任务自身 | 我希望避免无效配置 |
| 时间冲突提示 | 依赖与排期冲突提示 | 若 B 依赖 A，且 `B 开始日期 <= A 结束日期`，则判定潜在冲突，显示 ⚠ 与警示样式连线 | 我希望快速发现需求关系和当前工作排期之间的矛盾 |
| 冲突处理 | 不自动调整日期 | 只提示，不自动把 B 移到 A 之后 | 我希望依赖关系辅助规划，而不是系统擅自修改我的计划 |
| 拖动反馈 | 拖动后重新校验 | 调整子任务日期后，实时重算母任务排期与依赖冲突 | 我希望调整计划后立即知道新的日期是否符合依赖关系 |
| 关系范围 | 仅母任务之间建立依赖 | 不支持子任务 ↔ 子任务、子任务 ↔ 母任务 | 我希望现阶段保持规划模型简单 |
| 进度无关 | 不判断"是否完成" | 依赖仅代表需求 / 工作顺序，不依据完成状态解锁后续任务 | 我希望它服务于工作规划，而不是执行流程审批 |

### 2.6 数据保存与本地导入导出（新增）

| 模块 | 功能点 | 交互 / 规则 | 用户故事 |
| - | - | - | - |
| 数据保存 | 自动保存 | 新增、修改日期、拖动、设置 / 删除依赖、导入后均实时保存，无"保存整个规划"按钮 | 我希望时间板本身就是计划结果，不需要额外点击保存 |
| JSON 导出 | 导出为本地 JSON 文件 | 顶部工具栏「导出」→ 系统保存对话框；默认文件名 `工作规划时间板_YYYY-MM-DD.json` | 作为规划者，我希望把当前规划导出成文件，用于备份、留档或发给同事 |
| 导出内容 | 全量规划数据 | 包含母任务、子任务、名称、起止日期、展开状态、依赖关系、导出时间与版本号 | 我希望导出的文件能完整还原我当前的规划 |
| 导出范围 | 导出全部而非仅可见区间 | 不受当前周 / 双周 / 月视图与筛选状态影响，始终导出完整数据 | 我希望切换视图不会导致导出内容缺失 |
| JSON 导入 | 从本地文件导入 | 顶部工具栏「导入」→ 选择本地 `.json` 文件；也支持拖拽文件到画板导入 | 我希望换电脑或误删数据后能用文件快速恢复规划 |
| 导入模式 | 覆盖 / 合并 | 导入前弹窗二选一：**覆盖**（替换全部数据）或 **合并**（按 `id` 匹配更新，新增项追加） | 我希望既能整体恢复，也能把别人规划的一部分合并进来 |
| 导入校验 | 文件格式校验 | 校验 JSON 可解析、版本兼容、必填字段完整、日期格式合法、`结束日期 >= 开始日期`、依赖 id 存在、无自我依赖与循环依赖 | 我希望导入坏文件时能明确知道哪里出错，而不是白屏 |
| 导入校验 | 错误处理方式 | 校验不通过时列出具体错误行并阻止导入，不写入任何数据；不静默丢弃异常数据 | 我希望导入失败不会破坏我现有的规划 |
| 导入前置确认 | 覆盖二次确认 | 选择"覆盖"时二次确认："将替换当前全部规划数据，是否继续？" | 我希望避免误操作清空已有规划 |
| 导入反馈 | 结果提示 | 成功后 Toast 提示"已导入 N 个母任务 / M 个子任务"，并自动重绘时间板、重算母任务排期与依赖冲突 | 我希望导入后立刻看到完整结果 |
| 数据安全 | 纯本地处理 | 导入导出全部在桌面应用本地完成，不上传服务器 | 我希望规划数据只在自己手里 |
| 容错 | 兼容缺省字段 | `endDate` 缺省视为与 `startDate` 相同；旧版本文件缺失字段时按默认值补齐 | 我希望旧文件也能正常导入 |

### 2.7 明确不做的事

| 模块 | 规则 | 说明 |
| - | - | - |
| 规划属性 | 不引入进度状态 | 不做"未开始 / 进行中 / 已完成 / 延期" |
| 规划属性 | 不显示完成百分比 | 不做 30%、80% 进度条 |
| 规划属性 | 不做逾期提醒 | 不因今天超过结束日期标红 |
| 规划属性 | 不做里程碑 / 关键路径 | 不处理关键路径与里程碑 |
| 依赖能力 | 不做自动排程 | 不根据依赖自动顺延日期 |
| 依赖能力 | 不做资源冲突解决 | 不自动解决工作量 / 负责人冲突 |
| 其他 | 不做工时统计、人员负载、实际开始 / 结束时间、风险管理 | 属于项目执行与进度管理范畴 |

* 子任务条宽度代表持续时间。

* 只填写开始日期未填写结束日期 → `结束日期 = 开始日期`，**默认工期 1 天**。

## 8. 需求依赖

### 8.1 定义与范围

* 统一关系：**当前母任务依赖某个前置母任务**（`B 依赖 A`，即 `A → B`）。
* 仅支持母任务 ↔ 母任务；不支持子任务 ↔ 子任务、子任务 ↔ 母任务。
* 依赖只表达**逻辑先后关系**，不依据完成状态解锁后续任务。

### 8.2 设置方式

```text
设置需求依赖

当前母任务
Slots第二期策略

前置母任务
☐ 埋点开发及接入
☐ Dummy机器人梯度
☑ Slots现状分析
☑ Slots第一期策略
☐ 日常/周任务系统

取消              保存依赖
```

* 候选列表**不显示自身**，防止自我依赖。
* 一个母任务可配置多个前置母任务（例如 VIP 系统依赖 3 个 → 保存后显示 `依赖 3`）。
* 一个母任务可被多个任务依赖，正反向关系由系统自动维护。
* 在弹窗中可单独解除某一条前置关系，不影响母任务本身。

### 8.3 循环依赖校验

已有 `A → B → C` 时，禁止再配置 `C → A`，保存时提示：

> 该设置会形成循环依赖，请调整前置母任务。

并阻止保存。

### 8.4 画板表现

```text
Slots现状分析        ━━━━━
                         ↘
Slots第一期策略          ━━━━━━━━━
                                  ↘
Slots第二期策略                     ━━━━━━━
```

* 使用较弱的细线 + 箭头，箭头方向：前置母任务 → 后置母任务。
* 顶部「显示依赖关系」开关可隐藏连线（不删除数据，`依赖 N` 标记可保留）。
* Hover 某母任务时，高亮：当前母任务、它依赖的母任务、依赖它的母任务、对应连线；其他无依赖任务维持正常显示，不置灰。

### 8.5 冲突判断与处理

判断规则（简单规则）：

```text
若 后置母任务开始日期 <= 前置母任务结束日期 → 存在潜在依赖冲突
```

* `A 结束 9/20，B 开始 9/20` → 提示冲突；`A 结束 9/20，B 开始 9/21` → 正常。
* 正常依赖用普通连线；冲突依赖使用警示样式（虚线 / 警示色），母任务行同时显示 ⚠。
* **只提示，不自动修改排期**：系统不得把 B 自动移到 A 之后。规划者可能有意让两个需求部分并行，是否调整由用户自行决定。
* 拖动或改期后自动重算：子任务日期变化 → 母任务排期重算 → 重新检查依赖 → 更新依赖线与冲突标识。

### 8.6 重要原则

> **依赖是"规划约束提示"，而不是"强制排程规则"。**

当前版本需求依赖的定义：

> **用于表达母任务之间的逻辑先后关系，并辅助发现工作规划中的潜在时间冲突。**

## 9. 数据保存与本地 JSON 导入 / 导出（新增）

### 9.1 设计原则

* 规划数据属于用户本地资产，**全部处理在桌面应用本地完成，不上传服务器**。
* 导入导出是"数据搬运"能力，不改变任何画板交互与排期规则。
* 导出恒为**全量数据**，不受当前视图（周 / 双周 / 月）、筛选与展开状态影响。

### 9.2 入口位置

顶部工具栏右侧：

```text
[ 导入模板 ]   [ 导入 JSON ]   [ 导出 JSON ]
```

* 导出：点击后生成文件，并通过系统保存对话框选择保存位置。
* 导入：点击后弹出系统文件选择框，选择 `.json` 文件；同时支持将 `.json` 文件拖拽到画板区域导入。
* 导入模板：点击后弹窗展示一份符合当前导入结构的 JSON 示例，支持一键复制，以便交给 AI 将自然语言规划整理为可导入 JSON。

### 9.3 导出规则

| 项目 | 规则 |
| - | - |
| 默认文件名 | `工作规划时间板_YYYY-MM-DD.json`（例如 `工作规划时间板_2026-09-17.json`） |
| 文件编码 | UTF-8（含 BOM 可选，建议保留以兼容 Excel / 记事本打开） |
| 导出内容 | 版本号、导出时间、全部母任务、子任务、起止日期、展开状态、依赖关系 |
| 日期格式 | `YYYY-MM-DD` |
| 母任务排期 | **不落库**，由子任务计算，导入时自动重算 |
| 成功后反馈 | Toast：`已导出 N 个母任务 / M 个子任务` |
| 失败后反馈 | 弹窗提示：`导出失败，请重试` |

### 9.4 导入规则

导入前弹窗：

```text
导入规划数据

文件：工作规划时间板_2026-09-17.json
解析结果：12 个母任务 / 46 个子任务 / 8 条依赖关系

导入方式
● 覆盖：替换当前全部规划数据
○ 合并：按任务 id 匹配，已存在则更新，新增项追加

取消                开始导入
```

| 项目 | 规则 |
| - | - |
| 覆盖模式 | 清空当前全部数据后写入文件内容；需二次确认："将替换当前全部规划数据，是否继续？" |
| 合并模式 | 按 `id` 匹配：已存在则更新名称 / 日期 / 依赖，不存在则追加；当前数据中文件里没有的任务**保留不动** |
| id 缺失处理 | 文件中任务无 `id` 时，合并模式下按"名称 + 开始日期"匹配，仍无法匹配则新建并生成新 id |
| 导入后处理 | 自动重绘时间板、重算母任务整体排期、重新校验依赖并更新冲突标识、自动保存 |
| 成功反馈 | Toast：`已导入 N 个母任务 / M 个子任务` |
| 失败反馈 | 弹窗列出具体错误并阻止导入，**不写入任何数据** |

### 9.5 导入校验清单

校验按以下顺序执行，任一环节失败即整体终止：

1. **文件类型**：扩展名为 `.json`，且是合法 JSON 文本；否则提示"文件格式不正确，请选择 JSON 文件"。
2. **版本兼容**：`version` 为主版本兼容范围内（当前 `1.x`）；主版本不一致提示"文件版本不兼容，请更新后再导入"。
3. **结构完整**：`tasks` 必须为数组；母任务 `name` 必填、`id` 唯一。
4. **子任务字段**：`name`、`startDate` 必填；`endDate` 可缺省（缺省视为等于 `startDate`）。
5. **日期合法**：格式为 `YYYY-MM-DD` 且为真实日期；否则提示具体任务与字段名。
6. **日期顺序**：`endDate >= startDate`；否则提示"结束日期不能早于开始日期"。
7. **依赖引用**：`dependsOn` 中的 id 必须存在于文件（合并模式下也允许存在于当前数据）中；否则提示"存在无效的前置任务引用"。
8. **自我依赖**：`dependsOn` 不得包含自身 id。
9. **循环依赖**：导入数据整体做一次环检测，存在环则提示"文件中存在循环依赖，请修正后再导入"。

### 9.6 JSON 数据结构

```json
{
  "version": "1.0",
  "exportedAt": "2026-09-17T10:30:00+08:00",
  "source": "工作规划时间板",
  "tasks": [
    {
      "id": "T-001",
      "name": "Slots 现状分析",
      "expanded": true,
      "dependsOn": [],
      "subTasks": [
        {
          "id": "S-001",
          "name": "数据采集",
          "startDate": "2026-09-14",
          "endDate": "2026-09-16"
        },
        {
          "id": "S-002",
          "name": "现状报告",
          "startDate": "2026-09-17",
          "endDate": null
        }
      ]
    },
    {
      "id": "T-002",
      "name": "Slots 第一期策略",
      "expanded": true,
      "dependsOn": ["T-001"],
      "subTasks": [
        {
          "id": "S-003",
          "name": "体验模板设计",
          "startDate": "2026-09-21",
          "endDate": "2026-09-23"
        },
        {
          "id": "S-004",
          "name": "策略开发",
          "startDate": "2026-09-24",
          "endDate": "2026-09-26"
        }
      ]
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| - | - | - | - |
| `version` | string | 是 | 结构版本号，当前 `1.0` |
| `exportedAt` | string | 否 | 导出时间，ISO 8601 格式 |
| `source` | string | 否 | 来源标识，固定 `工作规划时间板` |
| `tasks[].id` | string | 是 | 母任务唯一标识，合并导入时作为匹配键 |
| `tasks[].name` | string | 是 | 母任务名称 |
| `tasks[].expanded` | boolean | 否 | 展开状态，缺省 `false` |
| `tasks[].dependsOn` | string[] | 否 | 前置母任务 id 列表；缺省 `[]` |
| `tasks[].subTasks[].id` | string | 是 | 子任务唯一标识 |
| `tasks[].subTasks[].name` | string | 是 | 子任务名称 |
| `tasks[].subTasks[].startDate` | string | 是 | 开始日期 `YYYY-MM-DD` |
| `tasks[].subTasks[].endDate` | string \| null | 否 | 结束日期；为空视为等于开始日期（单日任务） |

> 说明：母任务的整体排期（最早开始 / 最晚结束）不写入文件，导入后由子任务自动重算，避免数据冗余与不一致。

### 9.7 与其他能力的联动

| 场景 | 规则 |
| - | - |
| 导入后依赖冲突 | 立即按 8.5 规则重新校验并展示 ⚠ 与警示连线 |
| 导入后视图定位 | 自动将时间轴定位到包含"最早开始日期"的周期，避免用户以为导入失败 |
| 导入 + 自动保存 | 导入成功即写入本地存储，无需额外保存操作 |
| 导出 + 依赖开关 | 依赖数据始终导出，与「显示依赖关系」开关状态无关 |
| 导出 + 搜索过滤 | 始终导出全量数据，与搜索过滤结果无关 |

## 10. 反馈与容错原则

| 类型 | 方式 | 示例 |
| - | - | - |
| 轻量操作 | Toast | `已调整至 9/23–9/25`、`已导出 12 个母任务` |
| 需阻止操作的错误 | 弹窗内错误信息 | `结束日期不能早于开始日期。`、`该设置会形成循环依赖，请调整前置母任务。` |
| 需关注但不阻止 | 页面警示 ⚠ | `当前计划与前置需求存在时间冲突。` |
| 破坏性操作 | 二次确认 | `将替换当前全部规划数据，是否继续？` |

自动保存原则：新增子任务、修改日期、拖动排期、调整母任务顺序、设置 / 删除依赖、导入完成后直接保存，页面无需"保存整个规划"按钮。

## 12. 验收条件

开发完成后，至少应保证以下完整操作链可以正常完成：

1. 用户可以切换**周 / 双周 / 月**。
2. 横轴显示真实具体日期，不使用周编号作为主刻度。
3. 用户可以前后切换时间周期并回到今天。
4. 用户可以通过母任务名称或展开箭头展开 / 收起母任务，并支持全部展开 / 收起。
5. 母任务可以正确汇总全部子任务的时间范围。
6. 用户可以通过 `+ 子任务` 添加子任务。
7. 用户可以直接双击时间轴日期快速添加子任务。
8. 只填写开始日期时，任务默认持续一天。
9. 用户点击子任务可以修改开始 / 结束日期；清空结束日期后恢复为单日任务。
10. 用户可以直接拖动子任务改变整体时间，也可以通过两端拉伸调整工期。
11. 拖动后任务持续天数保持不变，且日期按天吸附。
12. 点击与拖动可以正确区分，不会产生误操作。
13. 日期变化后母任务时间范围自动重算。
14. 用户可以设置一个或多个母任务作为前置依赖。
15. 系统禁止自我依赖和循环依赖。
16. 依赖关系可以通过时间线箭头显示，并可整体开关。
17. 排期与依赖关系冲突时能够显示 ⚠ 与警示连线。
18. 系统不会因为依赖冲突自动修改计划日期。
19. 子任务跨当前显示周期时可以正确截取可见部分。
20. 左侧任务和右侧时间线始终保持正确对应，横纵向滚动同步。
21. 用户可以搜索母 / 子任务并同步过滤时间线。
22. 所有编辑操作自动保存，刷新页面后数据不丢失。
23. **用户可以一键把当前规划导出为本地 JSON 文件，文件名默认带日期。**
24. **导出的 JSON 包含全部母任务、子任务、起止日期与依赖关系，且不受当前视图与筛选影响。**
25. **用户可以选择本地 JSON 文件导入，或通过拖拽文件导入。**
26. **导入时可选择覆盖或合并模式；覆盖模式有二次确认。**
27. **导入文件校验失败时给出明确错误提示，且不破坏现有数据。**
28. **导入成功后时间板立即重绘，母任务排期与依赖冲突重新计算。**
29. **导入的 JSON 文件存在循环依赖、自我依赖、无效日期或无效依赖引用时，能被正确拦截。**
30. **导入导出全部在本地完成，不涉及服务端上传。**
31. 用户可以从空白画板新建并重命名母任务。
32. 用户可以删除母任务；确认后，其子任务及相关正反向依赖同时清理。
33. 用户可以重命名和删除子任务；删除后母任务排期与依赖冲突立即重算。
34. 删除母任务或子任务前必须二次确认，取消操作不得改变数据。
35. 首次启动不写入演示任务，并明确提供新建和导入入口。
36. 母任务行固定提供修改、依赖、添加子任务、删除四个图标操作按钮，并具有明确的可访问名称。
37. Hover 母任务时只增强相关任务与连线，其他无依赖任务不置灰。
38. 用户可以拖动母任务上下调整顺序；排序自动保存，重新加载后保持不变。
39. 用户可以拖动子任务在所属母任务内上下调整顺序；排序自动保存，重新加载后保持不变。

## 13. 版本边界说明

当前版本明确不进入以下功能：

* 子任务 / 母任务完成状态
* 完成百分比
* 实际开始 / 完成时间
* 延期判断与逾期标红
* 风险管理
* 工时统计与人员负载
* 子任务级依赖
* 关键路径
* 自动排程与自动推迟后续需求
* 资源冲突自动解决
* **云端同步、多人协同、版本历史与自动备份**

这些属于**项目执行与进度管理 / 协同平台**范畴，而当前页面主要服务于**工作计划编排**。

> 如果继续做下一版原型，建议重点打磨：**点击日期快速新增、拖动整个任务、两端拉伸工期、周 / 双周 / 月切换、依赖关系可视化、本地 JSON 导入导出** 这六个交互。
