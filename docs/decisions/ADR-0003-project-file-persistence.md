# ADR-0003：以项目 JSON 文件作为命名规划的持久化边界

- 状态：Accepted
- 决策日期：2026-09-29
- 决策者：项目维护者
- 影响范围：项目切换、最近打开、自动保存、文件冲突、SQLite 元数据、旧数据迁移

## 背景

旧版本只有一个应用级 `pmplan.sqlite3` 画板。用户打开 JSON 时，文件内容被覆盖或合并到这一个画板；之后的编辑只写 SQLite，原 JSON 不会跟着更新。这样打开第二个规划后，自动保存没有文件身份，容易把不同规划混在一起或覆盖错误的内容。

产品需要让用户选择近期打开的项目，启动时默认恢复上次成功打开的项目，并把修改写回打开时对应的 JSON 文件。同时仍需保留现有 JSON 导入的覆盖 / 合并语义、导出另存副本、SQLite 事务校验和未命名旧工作区。

## 决策

### 1. 项目文件与事务缓存

1. 每个命名项目由一个规范化绝对路径标识，规划 JSON 使用现有 `version: "1.x"` 结构。
2. 命名项目的 JSON 是用户可见的规划数据源，保存任务、子任务、依赖、排序和展开状态；视图设置不进入 JSON。
3. Rust `Storage` 继续以 SQLite 维护当前项目的事务缓存、校验和恢复能力。SQLite 还保存活动项目、最近项目、文件指纹、保存状态和按项目路径隔离的视图设置。
4. SQLite 事务提交和 JSON 回写不是跨存储单一事务。若 JSON 写入失败，缓存保留未保存状态，界面不得显示“已保存”。

### 2. 打开、新建、最近项目和启动恢复

* **打开项目**先读取并完整校验目标 JSON，再在一次 SQLite 事务中替换当前缓存；打开项目是项目切换，不触发导入覆盖 / 合并选择。
* **新建项目**先通过保存对话框写入合法空 JSON，写入成功后才建立活动项目并切换；取消或失败不会改变当前项目。
* **最近项目**保留最多 8 个规范化路径。成功打开、新建或另存为后置顶并去重；文件失效时保留状态和原因，用户可以移除记录，但移除只删除元数据，不删除源文件。
* **启动恢复**优先验证并打开上次成功打开的路径。路径不存在、不可读或 JSON 无效时保留失效条目并进入项目选择入口，不创建空项目覆盖该路径。

### 3. 自动回写与文件保护

1. 命名项目的规划变更先通过现有 Rust SQLite 事务提交，再生成完整规划 JSON 并回写当前活动路径；未命名旧工作区在另存为前只写 SQLite。
2. 每次成功读写记录文件修改时间、文件大小和内容哈希。下一次写入前必须同时比较修改时间与内容哈希；指纹变化、文件删除、权限不足或目标目录不可写时暂停自动回写。
3. 写入使用目标文件同目录的临时文件，完成并校验后原子替换原文件，成功后更新活动项目和最近项目指纹。
4. 外部修改冲突进入 `conflict` / `unsaved` 状态，提供以下用户动作：
   - **重新加载**：确认后丢弃当前未保存缓存，重新读取外部 JSON；
   - **另存为**：把当前缓存写入新路径，成功后切换活动项目；
   - **取消**：保持当前缓存、原路径和冲突状态，不静默覆盖外部文件。

### 4. 视图设置和导入边界

* `viewMode`、锚点日期、依赖显示、任务列宽和母任务排序模式按规范化项目路径写入 SQLite 元数据；缺少记录时使用默认值。持久化 `ViewMode` 仍只有 `week | biweek | month`，季度总览继续是临时浏览状态。
* **导入 JSON**仍作用于当前项目缓存，覆盖模式仍二次确认，合并模式仍按 `id` 更新并追加；完整校验或事务失败时不污染当前缓存。导入成功后按当前项目自动回写规则保存。
* **导出 JSON**仍是当前完整规划的另存副本，不改变活动项目路径、最近项目顺序或视图设置。
* **打开项目**不等同于导入，不改变原项目内容，也不允许以覆盖 / 合并选项代替项目切换。

### 5. 旧 SQLite 数据迁移

首次升级发现没有活动 JSON 路径但 SQLite 中存在规划数据时，显示一次“另存为 JSON”提示。用户可以立即另存为并建立命名项目，也可以暂缓迁移继续使用未命名工作区。迁移成功前不删除、不清空、不覆盖原 SQLite 数据；暂缓的工作区不伪装成已有 JSON 项目。

## 理由

* JSON 文件路径提供了清晰的项目身份，打开 A 后再打开 B 时，后续写入可以分别落到 A 和 B。
* SQLite 保留了当前已有的事务、依赖校验、回滚和浏览器内存适配器边界，避免把复杂关系校验移到文件写入代码。
* 修改时间与内容哈希共同检查可以覆盖文件系统时间粒度不足或外部工具保留时间戳的情况；冲突时显式交给用户选择，避免静默覆盖。
* 视图设置留在应用元数据，既能按项目恢复浏览状态，也不会污染用户可交换的规划 JSON。

## 备选方案

### SQLite 保存多个项目、JSON 只做镜像

不采用。SQLite 可以保存多个项目，但 JSON 与数据库之间仍没有跨存储原子提交，用户打开的文件无法自然成为唯一可见源文件；镜像失效和切换时序也会增加恢复分支。

### 打开项目时复制 JSON，之后只写 SQLite

不采用。它无法满足修改回写对应 JSON 的需求，且用户在外部编辑原文件后不会得到明确冲突提示。

### 前端直接写任意 JSON 路径

不采用。文件路径、校验、原子替换和权限错误必须集中在 Rust 存储层，前端只能使用业务级 gateway 命令。

## 影响

### 正向影响

* 用户可以在最近列表中选择最多 8 个规划，重启后回到上次项目。
* 每个项目的任务修改写回对应 JSON，项目之间不会因共享单一缓存而互相覆盖。
* 外部修改、写入失败和旧数据迁移都有明确状态与恢复路径。
* 现有导入覆盖 / 合并、导出另存、SQLite 事务和离线运行能力继续保留。

### 成本与约束

* SQLite 提交与 JSON 回写分两步，必须持久化保存状态并覆盖重试、另存为和冲突处理。
* 需要维护路径规范化、指纹计算、同目录临时文件替换以及 Windows 权限错误映射。
* 最近项目元数据可能包含失效路径；清理记录不能删除用户源文件。
* 命名项目文件格式仍需保持 `1.x` 兼容；视图设置变化不应修改规划 JSON。

## 验证要求

* Rust 测试覆盖 A/B 打开与自动回写隔离、原子写入、修改时间 + 哈希冲突、保存失败状态、MRU 上限和旧 SQLite 迁移。
* TypeScript / React 测试覆盖项目选择器、启动恢复、失效条目、保存状态、冲突三分支，以及打开与导入边界。
* 回归测试确认导入覆盖二次确认、合并按 `id` 追加 / 更新和导出另存语义不变。
* `git diff --check`、Markdown 检查、Rust 测试和 TypeScript 测试必须在发布前执行；桌面文件权限与真实视口证据缺失时在验收矩阵标记 `Pending`。

## 与既有 ADR 的关系

本 ADR 不替代 ADR-0001 的本地优先 Tauri 形态，也不替代 ADR-0002 的 Rust / SQLite 事务边界；它只细化命名项目的文件持久化范围，并明确原有“SQLite 唯一权威”和“直接 JSON 不采用”表述的适用边界。ADR-0001 与 ADR-0002 保留历史决策并附本范围澄清。
