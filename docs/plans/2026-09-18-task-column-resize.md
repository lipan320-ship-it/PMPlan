## 背景与目标

任务名列当前固定为响应式 CSS 宽度，长任务名容易被省略。增加可拖动分隔柄，允许用户拉宽或缩窄任务名列，并在重启后恢复选择的宽度。

## 范围

### 本次做

- Pointer Events 拖动调整任务名列宽度。
- 键盘方向键、Home、End 调整列宽。
- 统一最小值 240px、最大值 600px 和默认值 348px。
- 将列宽加入 ViewSettings，并贯通 Memory、Tauri、Rust、SQLite 持久化。
- 兼容旧 SQLite 数据库并补充测试和验收文档。

### 本次不做

- 不改变任务数据模型、任务排序、日期拖动或依赖计算。
- 不改变任务名称的单行省略显示规则。
- 不增加列宽导入导出字段。

## 方案

`TimelineBoard` 管理经过 clamp 的列宽状态，使用 CSS 自定义属性作为布局单一事实来源；拖动过程中只更新 React 状态，Pointer Up 时保存一次 ViewSettings。键盘调整复用同一 clamp 规则。任务列宽参与时间轴可用宽度计算，保持左右行对齐和横向滚动。

ViewSettings 新增 `taskColumnWidth`。Rust SQLite 使用 schema version 2 增加带默认值的列，旧数据库加载时获得 348px。非法值在前端和 Rust 保存/加载时回退或拒绝，避免布局异常。

## 受影响的页面流程与用户活动

用户在工作规划时间板任务名列右边界按下分隔柄并横向拖动，左侧列和右侧时间轴实时重排；松手后自动保存。键盘聚焦分隔柄后使用左右方向键微调，Home/End 设置边界值。重新打开应用后恢复上次保存宽度。

## 关键决策与取舍

- 保存 CSS 像素整数，不保存由视口推导的最终日期列宽。
- 最大宽度限制为 600px，避免时间轴被任务列挤压；窄屏仍允许时间轴横向滚动。
- 拖动不高频写库，保存失败保持当前布局并通过现有 Toast 提示。

## 风险与假设

- jsdom 无法验证真实 sticky、触控和布局尺寸，需要开发服务器下进行真实视口检查。
- 旧数据库必须通过独立迁移获得新列，不修改历史初始迁移。

## 验收口径与验证命令

- 可用鼠标/触控拖动列宽，宽度限制在 240–600px。
- 键盘调整可用且有 ARIA 当前值。
- 列宽保存后重新加载恢复，旧数据库默认为 348px。
- 左侧 sticky、左右行对齐和窄屏横向滚动无回归。
- 验证：`npm run check:web`、`npm run check:rust`，并运行 `npm run dev` 做宽屏、1080px、700px、320px 视口检查。
